# 花漾生活 — 前台重新設計：Sitemap / User Flow / Wireframe

> 第一階段交付物（資訊架構，與視覺風格無關）。
> 原則：**保留現有商業流程與 API**，僅優化 UX 結構、資訊層級與互動。

---

## 1. 現況盤點（Audit）

### 1.1 現有前台頁面與 API 對應

| # | 頁面 | 路由 | 主要 API | 角色支援 |
|---|------|------|----------|----------|
| 1 | 首頁 / 商品列表 | `/` | `GET /api/products?page=` | 訪客 + 會員 |
| 2 | 商品詳情 | `/products/:id` | `GET /api/products/:id`、`POST /api/cart` | 訪客 + 會員 |
| 3 | 購物車 | `/cart` | `GET/POST/PATCH/DELETE /api/cart` | 訪客(X-Session-Id) + 會員(JWT) |
| 4 | 結帳 | `/checkout` | `GET /api/cart`、`POST /api/orders`、`POST /api/payments` | 訪客 + 會員 |
| 5 | 登入 / 註冊 | `/login` | `POST /api/auth/login`、`/register` | 訪客 |
| 6 | 我的訂單 | `/orders` | `GET /api/orders` | 會員 |
| 7 | 訂單詳情 | `/orders/:id` | `GET /api/orders/:id`、付款回查 | 會員 |
| 8 | 404 | `*` | — | 全部 |

### 1.2 既有商業規則（不可變動）

- **雙模式認證**：`Authorization: Bearer <token>`（會員）或 `X-Session-Id`（訪客）。
- **免運門檻**：消費滿 **NT$ 500** 免運；未達門檻運費 **NT$ 150**。
- **訂單狀態**：`pending`(待付款) → `paid`(已付款) ／ `failed`(付款失敗)。
- **建立訂單** = SQLite transaction：同時扣庫存 + 清空購物車。
- **金流**：ECPay 綠界，建立訂單後導向付款，回查付款結果。
- **商品欄位**：`name, description, price, stock, image_url`（目前**無分類欄位**）。

### 1.3 現況 UX 痛點

| 痛點 | 說明 | 重設計對策 |
|------|------|-----------|
| 首頁資訊雜亂 | Hero→精選→品牌故事→全部商品→評價→服務 全擠在單欄 | 重新分區、建立清楚的「瀏覽 vs 說服」節奏 |
| 無商品篩選/排序 | 商品多時無法快速找到 | 加入排序（價格/上架）、價格區間、關鍵字搜尋（前端可做，API 已支援分頁） |
| 無分類導覽 | DB 無 category，但用戶心智需要分類 | 以「場合 / 花材類型」做**前端虛擬分類**（標籤），不動 API/DB |
| 加入購物車無回饋 | 僅有 notification | 加入「迷你購物車側欄 / Toast + 角標動畫」 |
| 結帳缺信任感 | 表單樸素、無金流方式可視化 | 加步驟條、付款方式圖示、安全標章、訂單摘要 sticky |
| 訪客結帳路徑不明 | 訪客可結帳但引導不足 | 結帳明示「訪客結帳 / 登入享訂單追蹤」 |
| RWD 僅斷點堆疊 | 無真正行動體驗 | 建立 Mobile-first 元件（底部導覽、抽屜選單、sticky 加購列） |
| 無麵包屑/回上頁 | 詳情頁迷失 | 加入麵包屑與「繼續購物」 |

## 3. User Flows（使用者流程）

### 3.1 主轉換流程：瀏覽 → 購買（訪客 & 會員共用）

```
[首頁/列表] ──點擊商品──▶ [商品詳情] ──加入購物車──▶ (Toast + 角標+1)
     │                          │
     │ 立即購買                  └──繼續購物──▶ [列表]
     ▼
[購物車] ──檢視/調整數量──▶ [前往結帳]
     │
     ▼
[結帳] ── 填收件資訊 ──▶ 選付款方式 ──▶ 送出
     │                                   │
     │ (POST /api/orders, transaction)   ▼
     │                            導向 ECPay 付款頁
     ▼                                   │
[訂單詳情] ◀── ECPay 回調 + 付款結果回查 ─┘
     status: paid ✓ / failed ✗ / pending …
```

### 3.2 認證分支（雙模式）

```
進入購物車/結帳
   │
   ├─ 已登入(JWT) ─────────▶ 正常流程，訂單綁定帳號
   │
   └─ 未登入 ── X-Session-Id ─▶ 訪客可繼續
                                ├─ 結帳頁提示：「登入以追蹤訂單」（非強制）
                                └─ 登入後 → 購物車自動合併(沿用現有 session 行為)
```

### 3.3 登入 / 註冊流程

```
[登入頁]
  ├─ 頁籤：登入
  │     輸入 Email + 密碼 ─▶ POST /auth/login
  │        ├─ 成功 ─▶ 存 token ─▶ 回前頁(或首頁)，導覽列顯示會員
  │        └─ 失敗 ─▶ 統一錯誤「Email 或密碼錯誤」
  │
  └─ 頁籤：註冊
        Email + 密碼(≥6) + 姓名 ─▶ POST /auth/register
           ├─ 成功 ─▶ 自動登入 ─▶ 回前頁
           └─ 失敗 ─▶ 欄位級錯誤提示
```

### 3.4 訂單查詢流程（會員）

```
[我的訂單] ──狀態篩選(全部/待付款/已付款/失敗)──▶ 清單
     │
     └─點擊──▶ [訂單詳情]
                 ├─ 待付款 ─▶ 「重新付款」按鈕 → ECPay
                 └─ 付款回查中 ─▶ loading → 更新狀態
```

## 5. 響應式斷點規範

| 斷點 | 寬度 | 商品網格 | 導覽 | 關鍵調整 |
|------|------|---------|------|---------|
| Mobile | < 640 | 2 欄(卡片) / 詳情單欄 | 漢堡 + 底部 Tab Bar | sticky 加購/結帳列、抽屜選單 |
| Tablet | 640–1023 | 2–3 欄 | 精簡橫向 + 漢堡 | 結帳 1.5 欄、摘要可摺疊 |
| Desktop | ≥ 1024 | 3–4 欄 | 完整橫向導覽 + 下拉 | 雙欄結帳、sticky 摘要、hover 互動 |
| Wide | ≥ 1440 | 內容 max 1200–1280 置中 | — | 加大留白與圖片尺寸 |
